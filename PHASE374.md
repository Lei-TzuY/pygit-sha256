# Phase 374 — Failure-atomic clone-origin finalization

Phase374 hardens Phase372's Git-compatible `clone -o/--origin` finalization when a completed non-empty clone must move its local `origin` namespace to another remote name.

## Why this phase

Phase372 correctly retargets legacy remote configuration, Git-style configuration, remote-tracking refs, native-object maps, partial-clone promisor metadata, and `extensions.partialClone`. Those pieces are stored in several files/directories and are updated sequentially. An I/O or injected failure after an early rename could therefore leave a clone with a partially moved namespace.

Phase374 adds a narrow rollback boundary around this clone-finalization operation. It does not replace the generic remote lifecycle and does not claim cross-process crash atomicity.

## Rollback surface

Immediately before the first retarget mutation, pygit snapshots the exact contents of only the metadata that this finalizer may modify:

- `.pygit/config.json`;
- `.pygit/config`;
- `.pygit/packed-refs`;
- `.pygit/native-map.json`;
- `.pygit/promisor.json`;
- `.pygit/refs/remotes/**`;
- `.pygit/logs/refs/remotes/**`.

If remote lifecycle rename, promisor retargeting, or final partial-clone config update raises, those paths are restored to their pre-operation contents and file modes before the original error is re-raised.

The rollback deliberately excludes:

- `.pygit/objects`;
- HEAD and local branch refs;
- index/worktree data;
- shallow state.

Clone-origin retargeting does not own those surfaces and rollback must not overwrite unrelated repository state.

## Security and concurrency boundary

Metadata symlinks inside the rollback surface are rejected before mutation instead of being followed. This prevents a rollback snapshot/restore from becoming an unexpected write outside `.pygit`.

This is same-process failure atomicity, not a claim of a durable multi-file transaction against power loss or arbitrary concurrent writers. Existing ref locks/CAS and the generic remote lifecycle remain responsible for their own concurrency semantics.

## SHA-256-native invariants

The phase changes failure handling only.

- remote-native identities remain genuine complete 40-hex SHA-1 values;
- local object/ref identities remain genuine content-derived 64-hex SHA-256 values;
- object-store content is outside the snapshot and is never rewritten by rollback;
- native maps are restored byte-for-byte, not regenerated by padding/translating ids;
- promisor native identities are restored byte-for-byte on failure;
- no zero-id or surrogate SHA-256 is introduced.

## Tests

`tests/test_phase374.py` injects failures after generic namespace rename, before promisor publication, and after promisor publication but before partial-clone extension finalization. Each case verifies exact metadata restoration and unchanged object-store state. Additional regressions cover successful retargeting, the `origin -> origin` zero-mutation fast path, promisor collision preflight, symlink rejection, and explicit reporting when rollback itself fails.
